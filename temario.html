Los 16 capítulos con sus secciones, sus laboratorios y el patrón que nace en cada época. Está en revisión: todavía puede cambiar.

Parte 1 · La web del servidor

Antes de que el navegador hiciera algo, todo pasaba en el servidor. Aquí nacen la petición sin estado, el controlador y la plantilla.

01. La web de documentos (1991)

HTTP pide y responde sin recordar nada: URL, enlaces, formularios y la primera página.

  • Qué problema resolvía la web: compartir documentos entre laboratorios
  • URL, HTTP y HTML: las tres piezas de Tim Berners-Lee
  • Una petición y una respuesta, sin estado
  • Enlaces y formularios: GET y POST
  • Por qué un documento no alcanza para una aplicación
  • La lista de tareas como página estática: el ejemplo que se reconstruye en todo el curso

Laboratorios

  • Enviar un formulario y ver la petición HTTP cruda
  • El mismo URL pedido dos veces: el servidor no recuerda nada

El patrón que nace aquí: Petición y respuesta sin estado, la base de REST y de toda la web actual.

02. CGI: un programa por petición (1993)

El servidor lanza un programa en cada visita: entrada por variables de entorno, salida con print.

  • La idea de NCSA: que el servidor ejecute un programa
  • La interfaz: variables de entorno, stdin y stdout
  • Un script de CGI en Perl y en C, línea por línea
  • HTML armado con print
  • Los problemas: un proceso por petición, nada se recuerda, lógica y presentación mezcladas
  • Seguridad: la inyección de comandos en los scripts de CGI

Laboratorios

  • Simulador: 100 usuarios contra CGI, cuántos procesos y cuánta memoria
  • Un CGI de juguete: llena las variables de entorno y mira lo que recibe el programa

El patrón que nace aquí: Un programa que recibe una petición y devuelve una página, el antecesor de cada controlador.

03. Las soluciones del servidor (1995-2005)

FastCGI, PHP, ASP, servlets y JSP, sesiones y los primeros frameworks MVC.

  • FastCGI y mod_perl: mantener el proceso vivo
  • PHP (1995): el código dentro del HTML
  • ASP (1996), los servlets de Java (1997) y JSP
  • ASP.NET WebForms y el ViewState: eventos de escritorio en la web
  • Cookies y sesiones: cómo la web aprende a recordar
  • Struts, Rails y Laravel: el MVC de servidor
  • Post/Redirect/Get: el formulario que no se envía dos veces

Laboratorios

  • La misma lista de tareas en CGI, PHP y un servlet con Front Controller, con el costo por petición
  • Una sesión por dentro: la cookie, el identificador y lo que guarda el servidor
  • Recargar después de enviar, con y sin Post/Redirect/Get

El patrón que nace aquí: Template View, Front Controller, MVC de servidor y Post/Redirect/Get.

Parte 2 · El navegador cobra vida

JavaScript llega al navegador y cada problema deja un patrón: delegar eventos, envolver el DOM, encadenar resultados, cargar solo lo necesario.

04. Llega JavaScript (1995)

DHTML, la guerra de navegadores y el DOM del W3C.

  • La historia del lenguaje, de Netscape y Brendan Eich a las versiones anuales, está en JavaScript, cap. 1 «Historia: de Netscape a las versiones anuales»
  • DHTML: capas, imágenes que cambian y menús desplegables
  • La guerra de navegadores: document.all frente a document.layers
  • El DOM nivel 0, 1 y 2 del W3C
  • Detectar el navegador frente a detectar la capacidad

Laboratorios

  • La misma acción en Netscape 4 y en Internet Explorer 5 (simulados)
  • El árbol del DOM de una página, nodo por nodo

El patrón que nace aquí: Detección de capacidades (feature detection), la base de los polyfills.

05. Técnicas de manipulación del DOM

innerHTML, createElement, fragmentos, reflujo, delegación de eventos y plantillas en el cliente.

  • Recorrer y seleccionar: getElementById, getElementsByTagName, querySelector
  • innerHTML frente a createElement y appendChild
  • DocumentFragment: trabajar fuera del documento
  • Reflujo y repintado: por qué tocar el DOM en un bucle es lento
  • Eventos: burbujeo, captura y delegación
  • Plantillas en el cliente: Mustache y Handlebars
  • El problema que queda abierto: mantener la pantalla igual a los datos

Laboratorios

  • Medidor: insertar 10 000 filas con cada técnica y ver el tiempo
  • Burbujeo y captura: sigue un clic por el árbol
  • Delegación: un solo manejador para mil botones

El patrón que nace aquí: Observer aplicado al DOM (eventos y delegación) y plantillas, la semilla del enlace de datos.

06. Ajax: la página que no se recarga (1999-2005)

XMLHttpRequest, Gmail y Google Maps, JSON y los problemas nuevos que trajo.

  • XMLHttpRequest nace en Outlook Web Access
  • Gmail, Google Maps y el artículo que le puso nombre (2005)
  • XML frente a JSON
  • Callbacks, estados de la petición y errores
  • Problemas nuevos: el botón Atrás, los marcadores y los buscadores
  • De XMLHttpRequest a fetch

Laboratorios

  • La lista de tareas que guarda sin recargar, con la petición a la vista
  • Los cinco valores de readyState en cámara lenta

El patrón que nace aquí: Comunicación asíncrona con el servidor y actualización parcial de la página.

07. jQuery y su época (2006)

El envoltorio del DOM, el encadenamiento de métodos y los plugins, y por qué hoy se usa poco.

  • Por qué existió: cada navegador con su propio DOM
  • El envoltorio: $() como fachada (Facade) sobre el DOM
  • La interfaz fluida: cada método devuelve el mismo objeto y las operaciones se encadenan
  • Eventos, animaciones y $.ajax
  • Los plugins ($.fn): extender un objeto compartido
  • $.Deferred: la promesa antes de las promesas
  • Prototype, MooTools, Dojo y YUI
  • Por qué hoy se usa poco: querySelector, fetch y navegadores uniformes

Laboratorios

  • Constructor de cadenas: arma $('li').addClass('x').fadeIn() y mira el objeto que pasa de un método al siguiente
  • El mismo código en jQuery y en JavaScript moderno, lado a lado
  • Escribe tu propio plugin

El patrón que nace aquí: Facade, interfaz fluida (encadenamiento de métodos) y plugins.

08. El estilo funcional llega al navegador

Encadenar resultados: Underscore y Lodash, promesas, observables e inmutabilidad.

  • Funciones como valores: lo que JavaScript heredó de Scheme
  • map, filter y reduce a fondo están en JavaScript, cap. 5 «JavaScript funcional»
  • Underscore y Lodash: _.chain
  • Promesas que se encadenan con .then (Promises/A+, 2012) y async/await
  • Observables y RxJS: flujos de eventos que se transforman como listas
  • Inmutabilidad y funciones puras: la base de los reductores de Redux

Laboratorios

  • Tubería de datos con _.chain: conecta pasos y mira cada resultado intermedio
  • Una búsqueda con autocompletado escrita con callbacks, con promesas y con un observable
  • Mutar frente a copiar: por qué la inmutabilidad hace fácil detectar cambios

El patrón que nace aquí: Composición de funciones y encadenamiento de resultados: tuberías, promesas y observables.

09. Módulos y carga diferida

Del caos de variables globales al patrón módulo, los empaquetadores y el lazy loading.

  • Variables globales y el caos de las etiquetas <script>
  • El patrón módulo (IIFE) y el revealing module
  • AMD y RequireJS: módulos que se cargan en el navegador
  • Empaquetadores: de Browserify y Webpack a Vite
  • División de código y carga diferida (lazy loading) de rutas con import()
  • CommonJS y ES Modules a fondo están en JavaScript, cap. 8 «Módulos: import, export y los dos sistemas de Node»

Laboratorios

  • Una aplicación que carga cada pantalla solo al visitarla, con la cascada de descargas a la vista
  • El grafo de dependencias de un proyecto y el paquete que produce

El patrón que nace aquí: Módulo (encapsulamiento) y carga diferida.

Parte 3 · Las aplicaciones en el cliente

La aplicación se muda al navegador. Llegan el MVC del cliente, la inyección de dependencias, el enrutador y el DOM virtual.

10. MVC en el cliente y Angular (2010-2016)

Backbone, Knockout, AngularJS con su enlace bidireccional e inyección de dependencias, y Angular con TypeScript.

  • Backbone: modelos, vistas, colecciones y eventos
  • Knockout: MVVM y observables
  • Ember: convenciones sobre configuración
  • AngularJS: directivas, enlace bidireccional y dirty checking
  • Servicios e inyección de dependencias: una idea del mundo Java llega al navegador
  • Angular (2016): reescrito en TypeScript, con decoradores, módulos, RxJS y carga diferida de rutas
  • Las señales del Angular actual

Laboratorios

  • Enlace bidireccional frente a actualización a mano
  • Dirty checking: cuántas veces se revisa cada vínculo en un ciclo
  • Un contenedor de inyección de dependencias que arma los servicios

El patrón que nace aquí: MVC, MVP y MVVM en el cliente, enlace de datos, inyección de dependencias y decoradores.

11. Aplicaciones de una sola página (SPA)

Enrutado en el cliente con hash y History API, y el costo de mover todo al navegador.

  • Qué es una SPA y qué gana
  • Enrutado en el cliente: el hash (#) y la History API
  • El estado en el cliente y en la URL
  • El costo: JavaScript inicial, pantalla en blanco e indexación por buscadores
  • Accesibilidad: el foco al cambiar de pantalla

Laboratorios

  • Una SPA mínima con su enrutador, escrita en 60 líneas
  • El tiempo hasta ver algo: página clásica frente a SPA

El patrón que nace aquí: Enrutador en el cliente.

12. React y el DOM virtual (2013)

La interfaz como función del estado, la reconciliación, Fiber y los hooks.

  • La idea: la interfaz como función del estado (UI = f(estado))
  • JSX y componentes
  • El DOM virtual y la reconciliación: comparar dos árboles y tocar solo lo que cambió
  • Listas y claves (key)
  • Flujo unidireccional, Flux y Redux
  • Fiber (2017): trabajo que se puede interrumpir
  • Hooks (2019)

Laboratorios

  • Qué nodos del DOM toca cada estrategia en un cambio: a mano, con jQuery, con dirty checking y con reconciliación
  • La reconciliación paso a paso entre dos árboles
  • Una lista con y sin key

El patrón que nace aquí: Interfaz como función del estado, DOM virtual, composición de componentes y flujo unidireccional.

13. Después de React: señales y Web Components

Reactividad fina con señales y componentes nativos del navegador.

  • Las señales: la idea de Knockout vuelve (Solid, Preact, Angular, Vue)
  • Web Components: Custom Elements y Shadow DOM
  • Vue y Svelte, comparados con Angular, están en Frontend, cap. 7 «Angular, Vue y Svelte comparados»
  • Cómo elegir hoy

Laboratorios

  • La misma actualización con DOM virtual y con señales: cuánto trabajo hace cada uno
  • Un Web Component que funciona dentro de cualquier framework

El patrón que nace aquí: Reactividad fina con señales y componentes nativos que sirven en cualquier framework.

SSR, SSG, hidratación, islas, Server Components y HTMX.

  • El péndulo: del servidor al cliente y de regreso
  • SSR, SSG e ISR

  • HTMX y la vuelta al HTML

El patrón que nace aquí: Islas, renderizado en el servidor con hidratación y HTML por la red (HTML over the wire).
